На поверхностный взгляд может показаться, что выражение "дистрибутивы GNU/Linux, основанные на исходных текстах" (Source Based GNU/Linux Distributions) не несёт дополнительного смысла, ведь все дистрибутивы GNU/Linux и так составляются из свободного и открытого программного обеспечения, распространяемого их авторами в форме исходных текстов. Но если мы посмотрим на такие дистрибутивы как Debian, Fedora, Arch, Guix, NixOS, Slackware, то увидим, что фактически единственной формой установки пакетов в них является бинарная форма. Это не значит, что в них не предусмотрена возможность сборки пакетов из исходников, однако к этим дистрибутивам не предоставляется удобных средств по конфигурированию и полной пересборке пакетов базовой системы из исходников и сборке собственного установочного образа. А некоторые, такие как Slackware, вообще распространяются исключительно в бинарной форме без предоставления средств сборки из исходников. Можно задаться вопросом, а могу ли я собрать из исходников собственный дистрибутив? Многие знают о существовании проекта Linux from Scratch (LFS), участники которого составляют руководство по сборке и установке системы GNU/Linux из исходных текстов. Ходит даже мнение, что каждый, кто считает себя специалистом в GNU/Linux, должен хотя бы раз в жизни собрать свой LFS. Для этого вам потребуется уже установленная система GNU/Linux, изнутри которой вы и будете производить сборку и установку LFS. Но зачем делать двойную работу, когда как-раз для желающих погрузиться во внутренности GNU/Linux и существуют дистрибутивы, основанные на исходных текстах.

Это первая статья из цикла, и в ней будет рассказано про эксперименты с дистрибутивом Void. В будущем планируется провести эксперименты с Gentoo и Alpine.

Итак, давайте уточним, что имеется в виду в этой статье под термином "дистрибутив, основанный на исходных текстах". Это такой дистрибутив, авторы которого свободно распространяют:

- Средства по сборке установочного образа полностью из исходных текстов всех его составляющих.
- Инструментарий и репозиторий описаний пакетов для сборки их из исходников.

Под такое определение подходят такие дистрибутивы как: [Void](https://voidlinux.org/), [Gentoo](https://www.gentoo.org/), [Alpine](https://alpinelinux.org/), [Crux](https://crux.nu/).

Не уникальной, но типичной для таких дистрибутивов, является возмножность начать развёртывание системы с минимального набора пакетов, постепенно конфигурируя и устанавливая необходимое для работы и получая достаточно простую, компактную и быструю программную систему.

Впервые Void я опробовал в 2024 г., загружая Live-систему на 64- и 32-разрядных ноутбуках. Система произвела приятное впечатление: загружалась быстро, XFCE и приложения работали исправно, тяжёлые сайты работыли без вопросов. И после выхода в феврале 2025 г. свежей сборки я решил устновить Void на один из старых ноутбуков. Это был Fujitsu Siemens LifeBook S6410 с процессором Intel Core 2 Duo T7500 и памятью DDR2 объёмом 4 Гб. Система успешно выполняла роль запасной рабочей и по совместительству экспериментальной. Недавно я переставил диск с нею на более старый и слабый LifeBook C1410 с процессором Core 2 Duo T5500 и памятью объёмом 3 Гб. И на нём она продолжает успешно выполнять свою роль. Но пришло время освоить Void более глубоко...

Void и другие дистрибутивы я буду устанавливать на следующие ноутбуки:

- Fujitsu Siemens LifeBook S7210 с процессором Intel Core 2 Duo T8300, памятью DDR2 объёмом 4 Гб и классическим жёстким диском SATA объёмом 160 Гб.

- Acer Aspire 5112WLMi с процессором AMD Turion64 x2 MT TL50, памятью DDR2 объёмом 2 Гб и классическим жёстким диском SATA объёмом 120 Гб.

Использование двух ноутбуков обусловлено двумя разными способами установки Void и его пакетов. В одном случае это будет установка бинарных пакетов, во втором -- сборка пакетов локально из исходников.

Оба ноутбука оснащены BIOS, что упрощает ручную разметку дисков и даёт возможность перестановки дисков с одного ноутбука в другой без потери способности загрузки с них.

Под каждый из трёх дистрибутивов на дисках будет выделено по 32 Гб, а всё остальное место будет отдано под раздел для `/home`, общий для всех трёх систем.

(Возможно вы заметили, что в списке не значится Crux. Дело в том, что мне нужно, чтобы дистрибутив поддерживал не только 64-разрядные системы, но и 32-разрядные. А Crux давно их не поддерживает. Однако, если с Gentoo или Alpine что-то пойдёт не так и раздел на диске останется вакантным, то эксперимент с Crux вероятно состоится. И да, эксперименты с 32-разрядными системами тоже планируются, но позже, а в параллели я уже экспериментирую с NetBSD на ноутбуке с Pentium M 2004 г.в.)

## Бинарная установка с использованием установщика

Самую первую установку Void я произвёл из Live-системы с рабочим столом XFCE4 с помощью штатного инсталлятора с текстово-графическим интерфейсом (TUI). Несмотря на старомодность, установщик прост в использовании, не требователен к ресурсам, и на выходе получаем точно такую же, готовую к использованию систему с XFCE. Но у этого установщика есть существенное ограничение: он не умеет создавать и подключать зашифрованные и LVM разделы. Я ставил Void на диск с уже существующим зашифрованным разделом для `/home`, оставшимся от старой Xubuntu. (К слову установщик [Calamares](https://en.wikipedia.org/wiki/Calamares_(software)) современной Ubuntu и многих других дистрибутивов, в отличие от старых родных инсталляторов, не умеет оперировать зашифрованными разделами.) Не беда, у меня уже был опыт ручного создания и подключение зашифрованного `/home`, описанный в одной из моих [статей]({% post_url 2023-07-17-how-to-make-home-in-linux-encrypted %}).

Если вы хотите получить быстрый старт с Void, то метод установки с использованием штатного инсталлятора будет оптимальным. Вы сможете освоиться с системой, привыкнуть к её менеджеру пакетов **xbps** и менеджеру сервисов **runit**, донастроить её под себя. Вы также сможете установить другой рабочий стол, такой как: Gnome, KDE, Cinnamon, Mate, Sway, Labwc или другой. Есть также вариант Live-системы без графической среды. Он может пригодиться для установки на сервер, на компьютер с ограниченными ресурсами или для ручной установки.

### Подготовка загрузочной флешки

Файлы iso с Live-системой можно загружать как с [родного](https://repo-default.voidlinux.org/live/) сервера, так и с [одного](https://mirror.yandex.ru/mirrors/voidlinux/live/) из зеркал. При этом файлы с подписью и проверочной суммой всё же рекомендую взять с родного сервера. Для тестирования и установки системы с графической оболочкой XFCE потребуется образ iso со словом `xfce` в его названии.

Перед записью Live-системы на флешку выясним точку её подключения:

``` sh
lsblk
```

Обычно это `/dev/sdb`.

Проверим также, не была ли она автоматически примонтирована:

``` sh
mount
```

И отмонтируем, если была примонтирована:

``` sh
umount /dev/sdb1
```

Наконец, запишем образ Live-системы на флешку:

``` sh
sudo dd if=void-live-x86_64-20250202-xfce.iso of=/dev/sdb bs=1M status=progress oflags=sync
```

Перед загрузкой с флешки рекомендую зайти в BIOS и установить правильное время UTC, которое отличается от московского на три часа в меньшую сторону. Однако, если компьютер будет подключён к Сети, то после загрузки в Void время будет обновлено с сервера времени.

Теперь можно перезагрузить компьютер с флешки, войти в терминале под пользователем `anon` и запустить установщик:

``` sh
sudo void-installer
```

Ну а я готов двигаться дальше и берусь за ручную установку Void без использования инсталлятора, но с использованием менеджера пакетов **xbps**.

## Ручная установка базовой системы

Итак, для ручной установки я воспользуюсь базовой сборкой Live-системы. На этом этапе эксперимента речь о сборке из исходников всё ещё не идёт. Я буду действовать в соответствии с [официальным руководством](https://docs.voidlinux.org/) Void.

### Подготовка загрузочной флешки

Нам потребуется базовый образ iso (со словом `base` в названии). Запишем его на флешку:

``` sh
sudo dd if=void-live-x86_64-20250202-base.iso of=/dev/sdb bs=1M status=progress oflags=sync
```

### Подготовка диска к установке

Загружаемся и входим в систему под пользователем `anon`. Можно и под `root`, так не придётся начинать большинство команд с `sudo`, но функционально интерфейс оболочки будет урезанным и неудобным.

Для начала зададим часовой пояс:

``` sh
sudo ln -sf /usr/share/zoneinfo/Europe/Moscow /etc/localtime
```

Я буду уставливать систему на старый HDD, поэтому сначала попрошу SMART диска провести его тестирование, которое выявит неисправные блоки (эта проверка займет в районе часа):

``` sh
sudo smartctl -t long /dev/sda
```

Теперь диск знает, где у него испорченные блоки, а мы можем приступить к созданию разделов и их форматированию. Создадим три первичных раздела одинакового размера (на диске 160 Gb их размер 32 Gb, на диске 120 Gb -- 24 Gb): на них будем устанавливать Void, Alpine и Gentoo. Оставшееся свободное место выделим под первичный раздел для LVM с разделами под `swap` и `/home`.

Для создания таблицы разделов воспользуемся `cfdisk` (первый раздел при этом отметим как загрузочный):

``` sh
sudo cfdisk /dev/sda
```

Можно проверить получившуюся таблицу, должно быть четыре раздела типа Linux:

``` sh
sudo fdisk /dev/sda
```

Void будем устанавливать на первый раздел, поэтому пока форматируем только его (другие два отформатируем, когда будем устанавливать другие системы):

``` sh
sudo mkfs.ext4 -c -L VOID /dev/sda1
```

Опция `-c` нужна для выявления испорченных блоков и исключения их из использования. Эта проверка замедляет форматирование, но я рекомендую её при использовании старых HDD, особенно, если вам уже известно, что на диске имеются испорченные блоки.

Убедимся, что файловая система не содержит ошибок:

``` sh
sudo fsck.ext4 /dev/sda1
```

Я не практикую шифрование системного раздела и поэтому здесь не описываю действия, необходимые для конфигурирования системы для загрузки с такого раздела. Но вы можете найти соответствующие подсказки в официальном руководстве Void.

Теперь займёмся шифрованным разделом для `swap` и `/home`.

``` sh
sudo cryptsetup luksFormat /dev/sda4
```

Подключим вновь созданный шифрованный раздел (`data` это название раздела для Device Mapper):

``` sh
sudo cryptsetup luksOpen /dev/sda4 data
```

Создадим на шифрованном разделе LVM-том (`data` это название LVM-тома, а ` /dev/mapper/data` -- подключённый зашифрованный раздел):

``` sh
sudo vgcreate data /dev/mapper/data
```

Создадим раздел для swap (`data` это наш LVM-том):

``` sh
sudo lvcreate --name swap -L 4G data
```

Наконец, создадим раздел для /home (обратите внимание на нижний регистр опции `-l`):

``` sh
sudo lvcreate --name home -l 100%FREE data
```

Отформатируем swap (опция `-c` нужна для проверки на испорченные блоки):

``` sh
sudo mkswap -c /dev/data/swap
```

Подключим swap:

``` sh
sudo swapon /dev/data/swap
```

Убедимся, что swap подключён:

``` sh
free
```

Наконец, отформатируем home:

``` sh
sudo mkfs.ext4 -c -L HOME /dev/data/home
```

### Установка системы

Примонтируем системный раздел:

``` sh
sudo mount /dev/sda1 /mnt
```

Примонтируем раздел home:

``` sh
sudo mkdir -p /mnt/home
sudo mount /dev/data/home /mnt/home
```

Скопируем ключи:

``` sh
sudo mkdir -p /mnt/var/db/xbps/keys
sudo cp /var/db/xbps/keys/* /mnt/var/db/xbps/keys/
```

Установим базовую систему и другие необходимые пакеты (пакеты будут загружены из сети):

``` sh
sudo xbps-install -Sy -R https://repo-default.voidlinux.org/current -r /mnt base-system lvm2 cryptsetup grub
```

Замените путь к репозиторию в опции `-R` на другой, если основной недоступен.

Создадим и заполним `/etc/fstab`:

``` sh
sudo xgenfstab /mnt > /mnt/etc/fstab
sudo echo "" | tee -a /mnt/etc/fstab
```
